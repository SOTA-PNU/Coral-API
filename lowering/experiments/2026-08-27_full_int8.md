# 완전 정수화 (full-int8) 작업 기록

목표: 추론 그래프의 **내부 연산 전부를 int8/i32 정수**로. f32 는 모델 ABI 경계
(입력 양자화 f32→i8, 출력 역양자화 i8→f32)에만 허용한다.

배경: PT2E 는 reference 표현(dq→float연산→q)을 내놓고, torch-mlir 의
`FuseQuantizedOps` 패스가 이를 정수 연산으로 접는다. 접는 패턴이 없는 연산은
float 로 남아 f32 디스패치가 된다. 산출물 규칙: 완전 정수화 빌드는
`build/<모델>_int8/` 로 분리 저장 (mainline 과 구분, manifest 의 model 필드로
check_result 판정 규칙 자동 상속).

측정 공통: MPACT coralnpu_v2 시뮬 (사이클=명령 수), 기본 피처
`+zve32x,+zvl128b` (resnet18 은 f32 reduction 이 남은 동안 `zve32f` 필요 —
LLVM 이 정수 전용 벡터에서 f32 리덕션을 스칼라화하다 크래시).

## 단계 1 — maxpool (2026-08-27, 완료)

- 증상: lenet5 dispatch_2/4 = `conv_..._f32` (maxpool 이 dq→f32→q 로 실행),
  vgg 의 2x2 f32 conv 4개, resnet 의 `conv_56x56x64x3x3_f32`(f32 풀링이 뒤
  conv 의 양자화 추적을 끊은 2차 피해).
- 원인 추적: ① XNNPACK quantizer 의 propagate_annotation 은 maxpool 을 전파
  목록에 포함 ✓ → ② FX op 는 `aten.max_pool2d` ✓ → ③ 진범:
  `FuseQuantizedOps.cpp` 의 `QuantInfo` 기본값 {0,1} 이 maxpool 피연산자 1
  (커널 크기 리스트!)의 양자화 추적을 요구 → "Partially traced" 로 포기.
- 수정 (torch-mlir 포크, patches/0001): relu 와 동일하게
  `QuantInfo<AtenMaxPool2dOp> = {0}` 특수화 +
  `QuantizeOperandsPastCommutingOps<AtenMaxPool2dOp,0>` +
  `QuantizeResultLikeOperand<AtenMaxPool2dOp>` 등록. maxpool 은 단조 연산이라
  양자화와 무손실 교환.
- 검증 방법: torch-mlir-opt 로 융합 패스 단독 실행 → maxpool 타입이
  qint8→qint8 로 바뀜을 IR 로 확인 후 전체 파이프라인.
- 결과 (lenet5_int8): 내부 f32 디스패치 2→0, 사이클 2,032,503→1,853,255
  (-8.8%, 스칼라 대비 -30.1%), 출력 **비트 동일** (상대L2 0.00).

## 단계 2 — resnet18/vgg: maxpool 여파 제거 + avg_pool2d (진행 중)

- 2a (maxpool 패치만, 측정 중): resnet 의 f32 conv·초기 dq, vgg 의 f32 conv
  4개가 사라지는지 확인. `reduction_*_i8xf32`(글로벌 평균)와 경계만 남을 것.
- 2b (avg_pool2d): torch 단계에서 adaptive_avg_pool2d 는 이미 aten.avg_pool2d
  로 분해되어 있고, TorchToTosa 의 tosa.avg_pool2d lowering 은 정수 누산
  (getAvgPool2dAccType, i8→acc i32)을 이미 지원한다. 따라서 단계 1과 동형의
  융합 패턴 3건(QuantInfo{0} + PastCommutingOps + ResultLikeOperand)만 추가
  (patches/0001, maxpool 과 통합). IR 검증: resnet 의 avg_pool2d 가
  qint8[1,512,7,7]→qint8[1,512,1,1] 로 융합됨.
- 평균은 정수 나눗셈 반올림이 있어 비트 동일 대신 허용치 검증 (분류 top-1 판정).
- 부수 기대: f32 reduction 이 사라지면 resnet18 도 기본 피처(zve32x, 정수
  전용)로 컴파일 가능해져 zve32f 예외가 불필요해진다.

### 단계 2 결과

**2a — maxpool 패치 재내보내기 (avgpool 융합 전):**

| 모델 | f32 디스패치 | 사이클 | 정확도 |
|---|---|---|---|
| vgg_cifar100_int8 | **경계 2개만** (입력 transpose, 출력 100) | 1,388,826,657(스칼라) → **412,543,934 (-70%, 3.4x)** | ✓ top-1 92 일치 |
| resnet18_int8 (zve32f, avgpool f32 잔존) | reduction + 경계 | 시뮬 **실패 stage=6** | ✗ |

- VGG 는 풀링이 전부 max 라 maxpool 패치만으로 완전 정수화 달성.
  이전에 "reduction_512x4"로 보인 것도 max 풀링 잔재였다.
- resnet 실패의 원인 규명: **MPACT coralnpu_v2 시뮬레이터의 ISA 에는 벡터
  float(vf*) 명령이 0개다 (Zve32x 전용).** zve32f 로 컴파일된 f32 리덕션의
  vfmacc 등이 미구현 → 트랩 → ebreak (stage 6, 1.8M 사이클에서 정지).
  RTL/cocotb 의 float RVV 테스트는 RTL 전용 기능이며 MPACT 에는 없다.
  → **교훈: 이 시뮬레이터에서 float 는 벡터화가 불가능하므로, 완전 정수화는
  성능 최적화가 아니라 벡터 실행의 전제 조건이다.** zve32f 사용 금지.

**2b — avgpool 융합 + 기본 피처(zve32x): 구조 성공, 정확도 실패 (디버깅 중)**

| 항목 | 결과 |
|---|---|
| f32 디스패치 | 경계 2개만 (구조 목표 달성) |
| 컴파일/실행 | 기본 zve32x 로 정상 (zve32f 예외 소멸) |
| 사이클 | 8,008,297,884 → 2,609,931,118 (-67%, 3.1x) |
| 정확도 | **✗ 상대L2 0.997, top-1 646≠654** — 계산 오류 (반올림 수준 아님) |

디버깅 노트:
- TOSA 검사: avg_pool2d 자체는 i8/acc_i32/zp0 로 정상 형태.
- 용의자 1 (유력): resnet 의 maxpool 은 **padding=1** (lenet/vgg 는 무패딩).
  정수 maxpool 의 패딩 채움값이 -128 이 아니면 경계 픽셀이 오염되어 증폭된다.
- 용의자 2: avgpool 뒤 이중 requant 경로의 상수/zp.
- 판정 실험: avgpool 융합만 끈 이분법 빌드(resnet18_bisect, 스칼라)로
  maxpool 경로 단독의 정확도를 측정 중.

**집계 방식 정정**: "경계만 f32" 는 *디스패치 이름* 기준이다. i8 이름의
디스패치 내부에 quantize 의 float 시뮬레이션 체인(floor/ceil/select, manifest
의 floor=N 통계로 확인 가능)이 접혀 있을 수 있다. 완전 정수화의 엄밀한 지표는
TOSA op 통계(manifest.tosa_ops 의 float 계열 op 수)로 별도 추적한다.

### 2b 정확도 디버깅 궤적 (2026-08-27)

1. **이분법 v1** (avgpool OFF·스칼라): ✓ top-1 654 — maxpool·conv 연쇄 융합 무죄.
   단, 변인이 둘(융합 + 스칼라/벡터)이라 불완전한 판정이었음을 나중에 인지.
2. **그래프 무죄 입증**: 실패한 resnet18_int8 의 TOSA 를 x86 호스트로 컴파일해
   실행 → 상대L2 3.89e-02, top-1 654 ✓. **int8 그래프 수치는 정확하다.**
   ⇒ 버그는 RV32 벡터 코드젠(LLVM) 또는 시뮬레이터 벡터 의미론.
3. **용의 명령 좁히기**: 통과 3모델(lenet/charrnn/vgg) 벡터 커널의 합집합에
   없는 resnet 전용 벡터 명령 10종 추출 — vl2r/vs2r·vlse8/vle16(커스텀 구현),
   vrgather.vv/vrgatherei16.vv, vredsum.vs, vmacc.vv, vmerge.vvm, vmset.m.
   avgpool 상관관계의 재해석: **avgpool 융합이 켜져야 그 구역(NCHW→NHWC
   transpose 등)이 벡터로 내려가며 이 명령들을 처음 밟는다.**
4. **KAT 하네스** (`scratch/rvv_kat.py`): 어셈 스니펫을 플랫 바이너리로 조립해
   pybind 시뮬 ITCM 에 주입, 결과 메모리를 기대값과 대조. 용의 8종 단순형
   **전부 통과** — 기본 의미론은 정상. 버그는 LMUL/마스크/테일 조합 또는
   코드젠 상호작용으로 추정.
5. 진행 중: (a) resnet18_int8 스칼라 시뮬 (RV32 스칼라까지 정상인지 확정),
   (b) 마이크로 재현기 `models/model_rnmicro.py` — 512ch conv→avgpool→fc 를
   실제 파이프라인으로 벡터 빌드, 시뮬 수 초 재현 루프 확보 시도.

교훈(방법론): 이분법은 변인을 하나로. 타깃 실패는 먼저 **호스트 실행으로
그래프/타깃을 분리**하면 20분 시뮬 루프를 2분으로 줄일 수 있다.

### 판정 매트릭스 완성 (2026-08-28)

| 완전 int8 그래프 실행 | 정확도 | 사이클 |
|---|---|---|
| x86 호스트 | ✓ | — |
| RV32 스칼라 + MPACT | ✓ top-1 654, 상대L2 3.89e-02 | 7,980,178,133 |
| RV32 벡터(zve32x) + MPACT | ✗ 상대L2 0.997 | 2,609,931,118 |

⇒ 그래프·스칼라 코드젠·시뮬 스칼라 실행 모두 무죄. **버그는 벡터 경로 전용**:
LLVM RV32 zve32x 미컴파일 또는 KAT 12종(단순형 8 + LMUL 경계·stride224 등
고난도 4)이 못 덮은 시뮬 벡터 의미론. 진행: `--iree-flow-break-dispatch`
(+ `--iree-opt-const-eval=false` 필요 — 절단 패스가 const-eval JIT 모듈에서
main 을 못 찾는 함정) 호스트-시뮬 앞 4000B 대조 이진 탐색으로 첫 분기
디스패치 특정 중.

참고: 정수 avgpool 의 스칼라 이득은 미미 (8.008B→7.980B). 이 작업의 실익은
벡터 실행(2.6B, 3.1x)을 가능하게 하는 데 있다 — 정확도만 잡으면 된다.

### 원인 확정: IREE O2 벡터 코드젠 미컴파일 (2026-08-28)

절단 이진 탐색(호스트-시뮬 앞 4000B 대조, const-eval=false 필요)이
`@main:6` — layer1 의 3x3 int8 conv 커널 — 을 첫 분기 지점으로 특정.
같은 절단을 `--iree-opt-level=O1` 로 빌드하니 **일치**.

| k=6 절단 빌드 | 시뮬 결과 |
|---|---|
| O2 (기본) | 불일치 (첫 실데이터 원소부터) |
| **O1** | **일치** |

시뮬레이터 무죄 최종 근거: KAT 18종(단순형 8, LMUL 경계·stride224 4,
레지스터 그룹 교차 슬라이드/gather/madd 6) 전부 통과 + 스칼라 실행 정확.
⇒ **O2 에서 RV32 zve32x 벡터 커널 미컴파일** (llvm-cpu 코드젠 계열).

우회: `CORAL_IREE_EXTRA_FLAGS="--iree-opt-level=O1"` — 명령행 뒤에 붙어
기본 O2 를 덮어씀 (스크립트 수정 불요). 진행 중: ① 전체 resnet 을 O1 벡터로
빌드·시뮬 (실전 해제 확인), ② `--iree-llvmcpu-mlir-opt-level=O1` 만으로
고쳐지는지 (범인 패스 범위 축소 + 그래프 최적화 O2 유지 우회).

업스트림 보고용 재현체: resnet18 mlirbc + `--iree-flow-break-dispatch=@main:6`
+ O2/O1 대조, 대상 riscv32 zve32x zvl128b. (IREE 이슈감)

## 단계 4 — charrnn sigmoid/tanh (대기)

f32 159개 최대어. `tosa.table` 정수 LUT 경로. LSTM 되먹임 특성상 정확도
재검증 필수 (현 상대 L2 4~6% 대역 유지가 합격선).
